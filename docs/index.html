Active threat: vishing against Okta SSO High concern
Since January 2026, groups linked to ShinyHunters, Scattered Spider and Lapsus$ ('Scattered LAPSUS$ Hunters') have called staff and IT help desks, steering victims through fake Okta login pages in real time to capture passwords and MFA approvals. Push MFA with number matching does not stop it. Once inside Okta, they move into connected SaaS apps (Salesforce, Microsoft 365, Google Workspace) and steal data for extortion. Reported targets include financial services. Latest tradecraft (September): attackers keep access by enrolling their own Okta FastPass device, often an emulated Android phone, so a password reset alone does not remove them.
Assessment

It is unlikely (25-35%) that the September Okta bugs are being exploited at scale today, but a realistic possibility (40-50%) that exploitation follows now that details are public. It is highly likely (80-90%) that vishing against Okta-using organisations continues through the rest of 2026.

Moderate confidence. CISA KEV (catalogue 2026.10.08) and the CVE records were checked directly on 12 October; Okta's own advisory pages could not be reached and are cited from search results.

Recommended actions
  1. Check whether you run any of the listed self-hosted components and upgrade them to the fixed versions.
  2. If you used the Hyperdrive installer, rotate the OAuth client secret and clear old installer and agent logs, since they may hold secrets or SAML assertions.
  3. Move admins and help desk staff to phishing-resistant MFA (Okta FastPass, FIDO2 security keys or passkeys), then everyone else.
  4. Use Okta network zones to allow sign-ins only from expected networks and block anonymisers (VPNs, Tor, proxies).
  5. Tighten help desk checks before any password or MFA reset, for example a call back to a known number or manager approval.
  6. Alert on new Okta FastPass or authenticator enrolments, especially from emulated or unrecognised Android devices, and review existing enrolments after any suspected compromise.
  7. Watch the Okta System Log for new MFA enrolments or resets, sign-ins from new devices or locations, and new admin role grants, and alert on them.
  8. Block the Okta-themed malware URLs listed above (defanged) and warn Okta admins and developers not to download Okta tooling from unofficial GitHub repositories.

Lesson 286 · Enrichment techniques · cycle of 33, repeats on purpose

Matching threats to client assets

The most valuable enrichment is 'does this client have the thing?'. That needs an asset inventory: which vendors, products and versions each client runs, and which are internet facing. Vulnerabilities use CPE names (for example cpe:2.3:a:fortinet:fortios) to identify products.

Think of it like this: A recall notice for a car is only useful if you know which car you drive.
Why it matters for UK clients

Shodan and Censys searches with country:GB and a client's IP ranges show what they expose. Pair that with KEV each morning for a very high-value brief.

Enrichment tip

Keep a simple per-client file: vendor, product, internet facing (yes/no). Match each morning's CVEs against it. That is personalised intel.

Try it today

Write down the five most important internet-facing products for one client (VPN, firewall, email, remote access, website CMS).

Quiz: What does a CPE name identify?
Show answerA specific vendor and product (and optionally version) so vulnerabilities can be matched to it.

False positives and allowlists

A false positive is a harmless thing flagged as malicious. Feeds sometimes include shared infrastructure like Google DNS (8.8.8.8), Microsoft or Cloudflare IPs. Blocking these can take a client offline. Allowlists (MISP calls them warninglists) catch them before sharing.

Quick quiz: What is a MISP warninglist for?
Show answerFlagging indicators that are probably false positives, such as well-known legitimate services.
Review · first seen 3 days ago

STIX, TAXII and MISP

STIX is a standard format (JSON) for describing threat intel: indicators, malware, threat actors and the links between them. TAXII is a standard way to send STIX over the internet. MISP is popular free software for storing, enriching and sharing intel, and it speaks both.

Quick quiz: Which one is the format and which is the transport: STIX or TAXII?
Show answerSTIX is the format. TAXII is the transport.
Review · first seen 7 days ago

IOC vs IOA vs TTP

An IOC (indicator of compromise) is evidence something bad happened: a hash, IP or domain. An IOA (indicator of attack) is behaviour showing an attack in progress, like PowerShell downloading a file and disabling antivirus. TTPs are the attacker's habits described in general terms.

Quick quiz: Is 'a new admin account created at 3am followed by backup deletion' an IOC or an IOA?
Show answerAn IOA. It is suspicious behaviour, not a static artefact.
